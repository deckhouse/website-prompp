Это руководство в стиле «Hello, World!», которое демонстрирует, как установить, настроить и использовать простую инстанцию Deckhouse Prom++. Вы загрузите и запустите Deckhouse Prom++ локально, настроите его для сбора метрик о себе и тестовом приложении, а затем поработаете с запросами, правилами и графиками для работы с собранными временными рядами.

## Загрузка и запуск Deckhouse Prom++

[Установите](../installation/) последнюю версию Deckhouse Prom++ для вашей платформы.

Перед запуском Deckhouse Prom++ давайте его настроим

### Настройка Deckhouse Prom++ для мониторинга самого себя

Deckhouse Prom++ собирает метрики с целевых объектов, поочередно запрашивая их HTTP-эндпоинты с метриками. Поскольку Deckhouse Prom++ сам предоставляет данные о своем состоянии, он может также отслеживать и свое собственное состояние.
Хотя сервер Deckhouse Prom++, который собирает данные только о себе, не является очень полезным, это хороший стартовый пример. Сохраните следующий базовый конфигурационный файл под именем prometheus.yml:

```yaml
global:
  scrape_interval: 15s # По умолчанию опрос целевых объектов каждые 15 секунд. Эти метки будут прикрепляться ко всем временным рядам и алертам при взаимодействии с внешними системами (федерация, удаленное хранилище, Alertmanager).
  external_labels:
    monitor: 'codelab-monitor'
```

### Конфигурация опроса с одним эндпоинтом

В данном случае это сам Deckhouse Prom++.

```yaml
scrape_configs:
  #Название задания добавляется в метку `job=<job_name>` для всех временных рядов из данного задания.
  - job_name: 'promplusplus'
  
  #Переопределение глобального интервала опроса — для этого задания он будет каждые 5 секунд.
    scrape_interval: 5s
    static_configs:
      - targets: ['localhost:9090']
```

### Запуск Deckhouse Prom++

Чтобы запустить Deckhouse Prom++ с новым конфигурационным файлом, перейдите в каталог с бинарным файлом Deckhouse Prom++ и выполните:
По умолчанию база данных хранится в ./data (опция --storage.tsdb.path).

```yaml
./prompp --config.file=prometheus.yml
```

Deckhouse Prom++ должен успешно запуститься. Откройте браузер и перейдите на страницу статуса Deckhouse Prom++ по адресу:
http://localhost:9090. Дайте ему несколько секунд, чтобы собрать данные о себе через свой собственный HTTP-эндпоинт метрик.
Вы также можете проверить, публикует ли Deckhouse Prom++ свои метрики, перейдя по адресу:
http://localhost:9090/metrics.

### Использование браузера выражений

Давайте изучим данные, которые Deckhouse Prom++ собрал о самом себе. Перейдите во встроенный браузер выражений Deckhouse Prom++ по адресу http://localhost:9090/graph и выберите вид «Table» на вкладке «Graph».
Как можно увидеть на странице http://localhost:9090/metrics, одной из метрик, которую Deckhouse Prom++ экспортирует о себе, является prometheus_target_interval_length_seconds (фактический интервал между опросами целевых объектов). Введите следующее выражение в консоли запросов и нажмите "Execute" (Выполнить):
prometheus_target_interval_length_seconds

Это вернет несколько временных рядов (с последними сохраненными значениями), все с именем метрики prometheus_target_interval_length_seconds, но с разными метками, обозначающими различные процентильные задержки и интервалы группировки целей.
Если нас интересует только 99-й процентиль задержек, можно использовать следующий запрос:
prometheus_target_interval_length_seconds{quantile="0.99"}

Чтобы посчитать количество возвращаемых временных рядов, используйте:
count(prometheus_target_interval_length_seconds)

### Использование интерфейса графиков

Чтобы построить график по выражениям, перейдите на http://localhost:9090/graph и выберите вкладку «Graph».
Например, чтобы построить график скорости создания новых чанков в самосканируемом экземпляре Deckhouse Prom++, используйте:
rate(prometheus_tsdb_head_chunks_created_total[1m])

Попробуйте поэкспериментировать с параметрами диапазона и другими настройками.

### Перезагрузка конфигурации без перезапуска

Deckhouse Prom++ позволяет применять новую конфигурацию без перезапуска, отправляя процессу сигнал SIGHUP:

```yaml
kill -s SIGHUP <PID>
```

### Корректное завершение Deckhouse Prom++

Для корректного завершения работы Deckhouse Prom++ используйте сигнал SIGTERM:

```yaml
kill -s SIGTERM <PID>
```
