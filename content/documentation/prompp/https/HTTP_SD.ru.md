title: "HTTP Service Discovery (HTTP SD)"
weight: 38

---

Deckhouse Prom++ предоставляет универсальный механизм HTTP Service Discovery, который позволяет обнаруживать цели через HTTP endpoint.
HTTP Service Discovery является дополнением к поддерживаемым механизмам обнаружения сервисов и представляет собой альтернативу File-based Service Discovery.

## Сравнение File-Based SD и HTTP SD

Ниже представлена таблица сравнения двух наших универсальных реализаций Service Discovery.

| Параметр             | File SD                          | HTTP SD                          |
|----------------------|----------------------------------|----------------------------------|
| Основано на событиях | Да, через inotify                | Нет                              |
| Частота обновлений   | Мгновенно, благодаря inotify     | Согласно refresh_interval        |
| Формат               | Yaml или JSON                    | JSON                             |
| Транспорт            | Локальный файл                   | HTTP/HTTPS                       |
| Безопасность         | Права доступа к файлам           | TLS, Basic auth, Authorization header, OAuth2 |

## Требования к HTTP SD endpoints

Если вы реализуете HTTP SD endpoint, вам следует учитывать следующие требования.

Ответ потребляется "как есть", без изменений. С каждым интервалом обновления (по умолчанию: 1 минута) Deckhouse Prom++ будет выполнять GET-запрос к HTTP SD endpoint. GET-запрос содержит HTTP-заголовок X-Deckhouse Prom++-Refresh-Interval-Seconds с указанием интервала обновления.

SD endpoint должен отвечать с HTTP-кодом 200 и HTTP-заголовком Content-Type: application/json. Ответ должен быть в формате UTF-8. Если не нужно передавать цели, также должен возвращаться HTTP 200 с пустым списком []. Списки целей не упорядочены.

Deckhouse Prom++ кэширует списки целей. Если при получении обновленного списка целей происходит ошибка, Deckhouse Prom++ продолжает использовать текущий список целей. Список целей не сохраняется после перезапуска. Метрика prompp_sd_http_failures_total отслеживает количество неудачных обновлений.

Полный список целей должен возвращаться при каждом сканировании. Инкрементальные обновления не поддерживаются. Экземпляр Deckhouse Prom++ не отправляет свое имя хоста, и SD endpoint не может определить, является ли запрос SD первым после перезапуска.

URL HTTP SD не считается секретным. Аутентификация и любые API-ключи должны передаваться с использованием соответствующих механизмов аутентификации. Deckhouse Prom++ поддерживает TLS-аутентификацию, базовую аутентификацию, OAuth2 и authorization headers.

## Формат HTTP_SD

```yml
[
  {
    "targets": [ "<host>", ... ],
    "labels": {
      "<labelname>": "<labelvalue>", ...
    }
  },
  ...
]
```

**Примеры:**

```yml
[
    {
        "targets": ["10.0.10.2:9100", "10.0.10.3:9100", "10.0.10.4:9100", "10.0.10.5:9100"],
        "labels": {
            "__meta_datacenter": "london",
            "__meta_prompp_job": "node"
        }
    },
    {
        "targets": ["10.0.40.2:9100", "10.0.40.3:9100"],
        "labels": {
            "__meta_datacenter": "london",
            "__meta_prompp_job": "alertmanager"
        }
    },
    {
        "targets": ["10.0.40.2:9093", "10.0.40.3:9093"],
        "labels": {
            "__meta_datacenter": "newyork",
            "__meta_prompp_job": "alertmanager"
        }
    }
]
```
